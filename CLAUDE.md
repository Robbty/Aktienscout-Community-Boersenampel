### Cross-browser specifics (don't regress these)

- All extension JS uses `const api = globalThis.browser || globalThis.chrome;` — both expose promise-based MV3 APIs, so `await api.storage.local.get(...)` works in each. Never go back to bare `chrome.*`.
- Chrome background is a `service_worker` that pulls shared code via `importScripts('lib/ampel.js')`, guarded by `if (typeof importScripts === 'function')`. Firefox background is `"scripts": ["lib/ampel.js", "background.js"]` (event page; no `importScripts`). `lib/ampel.js` therefore also assigns its functions onto `globalThis` so both load paths work.
- `popup.js` talks to the worker via `api.runtime.sendMessage(msg)` (promise form) — not the callback form, which Firefox's `browser.*` ignores.

## What this project is

A tool to monitor the **"Börsenampel"** (stock traffic-light) of the Skool community *Aktienscout-Community* (`cybermoney-1123`) and detect changes since the user last looked. The data lives behind a personalized Skool login — only the logged-in user can reach it.

Source page (login-required, Next.js SPA):
`https://www.skool.com/cybermoney-1123/classroom/8d4e7683?md=<HASH>`

## The data model (most important thing to understand)

Skool is a Next.js app. **The entire ampel structure is embedded as clean JSON** in the page — do NOT scrape the rendered DOM. Read:

```
document.getElementById('__NEXT_DATA__')  →  props.pageProps.course
```

Tree shape:
- `course.course` — root ("Die Aktien-Ampel (lifetime)*"), has its own `updatedAt`.
- `course.children` — 5 sections: `Achtung zuerst lesen`, `Folgt in Kürze`, `grüne Ampel`, `gelbe Ampel`, `rote Ampel`.
- each ampel section's `children` — the stock modules, each `{ course.id, course.metadata.title, course.updatedAt }`.

Key facts that drive the whole design:
- **A stock's traffic-light color = which section it sits in.** There is no color field; membership is the signal.
- **Every stock carries its own `updatedAt` timestamp.** Change detection needs only this — one request to load the page/JSON reveals: stock moved between ampeln, stock added, stock removed, or a stock's analysis was edited. No per-stock content fetch required for the diff.
- Per-stock IDs are stable hashes, used as `?md=<HASH>` in the URL. Anchor logic on IDs + timestamps, never on HTML structure.
- **The rich text body of each stock** (the `[+]` analysis bullets, "Fazit", "(Letzte Sichtung: …)") is NOT in `__NEXT_DATA__`. Skool loads it separately per module on demand. Treat it as Tier 2 — fetch only when the user opens a stock or to show *what* changed in an already-flagged stock.

`boersenampel-baseline.json` is the first captured snapshot (full membership + timestamps) and doubles as the initial comparison baseline. Regenerate snapshots in the same shape for diffing.

## Architecture decision: browser add-on, not a standalone app

Chosen because the add-on runs inside the user's already-logged-in browser session:
- Auth is free — uses existing Skool cookies. No cookie-expiry handling, no login automation, no credential storage. This was the deciding factor over a Python app.
- Background polling via `chrome.alarms` + a cookie-authenticated `fetch()` of the page (same-origin → cookies attached), even with no tab open. Parse `__NEXT_DATA__` out of the returned HTML.
- Target Chromium first (covers Chrome/Edge/Brave/Opera with one build), then port to Firefox (core JS is shared; only manifest differences).

### How Phase 1 works (the two data paths + state model)

- **Two ways data arrives, by design.** (a) `content.js` runs on the ampel page and reads `__NEXT_DATA__` from the live DOM on every visit — guaranteed-authenticated, the robust path. (b) `background.js` does a cookie-authenticated `fetch()` on an alarm for true background polling without an open tab. If Chrome withholds session cookies from the background fetch (SameSite), path (a) still keeps data fresh. Both funnel through `ingestSnapshot()`.
- **State in `storage.local`:** `current` (latest snapshot), `baseline` (state the user last acknowledged via "Als gesehen markieren"), `settings.intervalMinutes`, `meta`. The popup's "since last visit" list is `diffSnapshots(baseline, current)`; notifications fire on `diffSnapshots(prevCurrent, newSnapshot)` between polls.
- **Logged-out privacy:** a failed poll never overwrites `current`/`baseline` (so the diff survives the logout gap), it only sets `meta.lastPollOk = false`. The popup shows ampel data *only* when `meta.lastPollOk === true`, and re-polls on every open (showing "Prüfe Login…" first) so cached paid data is never visible while logged out — yet all changes that happened while away appear on the next successful poll. **Freshness shortcut (v0.6.2):** if the last successful poll is younger than `FRESH_MS` (3 min, popup.js), the popup renders the stored state immediately and re-polls in the background (same for the Circle tab) — a deliberate small trade-off against the privacy rule to avoid the wait on quick re-opens.
- **Blinking toolbar icon:** MV3 workers sleep after ~30 s, so there is no persistent blink. Instead a ~12 s blink *burst* (`setInterval` toggling `ICON_ON`/`ICON_OFF` every 500 ms) fires when a poll finds pending changes, while the worker is still awake — background-alarm polls and content-script captures blink; popup-initiated and startup polls do not. `refreshBadge` heals a stuck frame and `stopBlink` runs when the count hits 0 (acknowledge). Toggleable via `settings.blinkEnabled`.
- **"Neue Seite" placeholders (Ampel side):** the author also creates empty "Neue Seite" modules at section (Menüpunkt) level of the ampel course (live 08/2026: four at once). `hiddenPlaceholderTitle` in `lib/ampel.js` (same rule as `circleHiddenTitle`, deliberately duplicated — the two libs must stay independently loadable) filters them out of `buildSnapshot` (sections AND stocks) and out of BOTH sides of `diffSnapshots` (old side too, so legacy stored snapshots don't fire one-time "removed" false alarms). That keeps them out of diffs, notifications, badge count and new history entries; the popup additionally filters legacy stored history events and snapshot rows when rendering "Statuswechsel" and "Zuletzt bearbeitet". Stored leftovers are DELETED once at startup by `cleanupPlaceholdersOnce()` in background.js (guarded by `meta.placeholderCleanupV1`): strips them from `baseline`/`current` via `stripHiddenFromSnapshot` (ampel.js, stockCount adjusted), from `history`/`circleHistory`, and from `circle.modules` — runs on onInstalled AND onStartup (the app fires onStartup via `__appFireStartup`). Renaming a placeholder to a real stock later shows up as a normal "added" event (same id, no longer hidden).
- **Snapshot shape** (`buildSnapshot` in `lib/ampel.js`): `{ courseTitle, courseUpdatedAt, stockCount, stocks{id->{id,name,section,color,updatedAt}}, sections{id->{id,title,color,updatedAt,hasStocks}} }`. `diffSnapshots` only computes section diffs when the *old* snapshot already has a `sections` field — and `ingestSnapshot` back-fills `baseline.sections` once — together preventing "everything new" false alarms after a version bump.

### Circle feature (Phase 1c) — how it works

- **Data model:** same Skool course tree, but the course's children ARE the positions (no color sections). Title conventions of the author (messy, parser is tolerant): `Name [57,75 € ]` = open position, bracketed price = the **day price at the time the entry was last edited** (per the user, 08/2026 — NOT a Kursziel; `titleInfo.currentPrice` keeps its name for stored-data compatibility, it only serves as the Yahoo symbol-plausibility anchor and a tooltip); since 08/2026 also double-price brackets `[30,64 Dollar / 26,44 €]` (Carnival) and `[118.14 € / 136,67]` (Alibaba) — the parser always takes the first €-tagged number inside the bracket (the EUR Kursziel) and ignores the dollar value; `Name [8 Tage]` = sold after 8 days. `Statistik` / `Statistik aktuell` = meta modules with the author's own totals (parsed as cross-check, shown in the popup).
- **The amounts live ONLY in each module's rich-text body** (`children[i].course.metadata.desc`, format `[v2][{ProseMirror-JSON}]`), which the tree carries only for the module selected via `?md=<id>`. Harvest path in `pollCircle()` (background.js): fetch course HTML once (tree + `buildId` + one desc), then per stale module `GET /_next/data/<buildId>/<community>/classroom/<course>.json?md=<id>` (cookie-auth). `buildId` rotates on Skool deploys → on failure re-scrape HTML once and retry. Incremental via `updatedAt` vs stored `bodyUpdatedAt` (`selectStaleModules`): first harvest ~20 requests (350 ms apart, capped at 25/run), later polls usually 0–2.
- **Body formats actually seen live** (all covered in `lib/circle.js` + `test/circle.test.mjs`): `Kauf am 03.08.2026 zu 48,88 $ (42,32 €) je Aktie` (€ in parens wins), `zu 27,85 $ / 24,03€ je Aktie` (slash form, 08/2026 — € after the slash wins, dollar value optional; per-share Kaufpreis ALWAYS comes from this "Kauf am …" line), the currency token may be `€`, `Euro`, `euro` or `EUR` everywhere (title bracket, Kauf/Verkauf line, Kaufpreis/Verkaufspreis, Ertrag/Gewinn/Verlust — `(?:€|euro|eur)`, case-insensitive; `$`/`Dollar`/`USD` are never read as EUR), `zu 3.39€` (decimal DOT — single dot + 1–2 decimals is parsed as decimal, not thousands), `12 Stück zum Kaufpreis: 509 € - Verkaufspreis: 560 € = 51 € Ertrag`, `… 645 € verkauft zu 712 € Gewinn: 47 €`, `Verkaufspreis: 54,54` (missing €), `Verkaufspreis: 785, €` (truncated decimals), and entries WITHOUT a Stück line (Heidelberg/Accor format) where Kaufpreis and title price share the same unit → unrealized = currentPrice − Kaufpreis (both live cases land exactly on the author's +10% scheme). Only parse RESULTS are stored, not the raw body — after a parser change bump `CIRCLE_PARSE_VERSION` (background.js): `doPollCircle` then clears every `bodyUpdatedAt` once so all bodies are re-fetched and re-parsed (self-healing if the harvest run breaks off early).
- **Aggregation** (`computePortfolio`, pure, runs in the popup — nothing aggregated is persisted, parser fixes retroactively fix all numbers): investedCumulative (labelled **"Kaufvolumen (kumuliert)"** since v0.8.1 — it is turnover, re-invested proceeds count again), `capitalNeed` (**"Eingesetztes Kapital"**, `computeCapitalNeed`: running max of buys − sell proceeds at day-end granularity = hard lower bound of deposits; user asked for this distinction 31.08.2026), deployedOpen, realized (explicit Ertrag/Gewinn wins over sell−buy difference), unrealizedTotal. **Kursziel of open positions (v0.6.9, user rule):** NOT the title price — derived from the body's Stück line `N Stück zum Kaufpreis: X € - Verkaufspreis: Y`. `Y = ?` → `targetTotalEur = X × TARGET_FACTOR (1.10)`, `targetSource 'computed'`; concrete `Y` → taken as is, `targetSource 'author'`, `targetOff = |Y/X − 1.10| > TARGET_TOLERANCE (0.03)` (popup renders the cell red + tooltip). `pos.currentPrice` = target per share (`/qty`, else same unit as Kaufpreis), so unrealized/sums/chart target line all follow; the title price (day price at last edit) survives as `pos.titlePrice` (tooltip only). Trigger: Wells Fargo 08/2026 — title `[92,32 Dollar / 79,11 €]` (=71,91 € +10 %) vs. body `7 Stück zum Kaufpreis: 575 €` (≠ 7 × 71,91) showed −3,7 % potential. Parse failures land in `unparseable` (rendered as "Nicht auswertbar"), never in totals; incomplete positions render dimmed and are excluded from sums.

Opening the Circle tab sends `circleSeen` → `pending = 0` → dot cleared. The popup shows the events in the collapsible "Käufe & Verkäufe" log (auto-expands while pending). **Duplicate protection (v0.6.6, live-observed bug):** both polls (`pollViaFetch`, `pollCircle`) sit behind in-flight guards (module-global promise, all callers join the running poll) because overlapping triggers (alarm × popup × standalone window × "Jetzt prüfen", esp. since the v0.6.2 non-awaited fresh path) diffed against the same old state and appended the same event batch twice; additionally every history append dedups on `id|type|at` (`appendUniqueHistory`/`historyKey` in ampel.js), `doPollCircle` writes `circle`+`circleHistory`+`circleMeta` in ONE `storage.local.set` (a worker death between separate writes silently lost events), and `cleanupHistoryOnce()` (guarded by `meta.historyCleanupV1`) heals pre-existing duplicates once at startup. Placeholder modules (`kind 'plain'` with no parsed trade, e.g. the author's empty "Neue Seite") produce NO bought/removed events; the bought event fires when the placeholder later becomes a real position (`circlePlaceholder` in circle.js). ## Event-log interface (v0.7.0, tag `events-v1`) — how it works

Full spec in `EVENTS.md` (format, folder layout, reducer contract); planning history in `Handoff-trader-schnittstelle.md`. Key implementation facts:

- **Libs** (all `globalThis`-exported, load order matters: quotes → ampel → circle → events → sync-*): `lib/events.js` (pure: `makeEvent`, `buildAmpelStockExport`/`buildCircleStockExport`/`buildAmpelPayload`, `eventsFromAmpelDelta` (input = `diffSnapshots` result, `edited` INCLUDED unlike the internal history), `eventsFromCircleDelta` (input = the already-deduped `fresh` array of `doPollCircle`), JSONL encode/parse (tolerant), `dayKey` (UTC), `sortEvents` `(at, producer.id, seq)`, `dedupeEvents` by `id`, `reduceEvents` = reference reducer), `lib/sync-webdav.js` (`createWebdavAdapter({baseUrl,user,password,fetchFn})`, MKCOL/PUT/GET/PROPFIND, never throws, `validateWebdavUrl` = https only, http only for loopback), `lib/sync-folder.js` (File System Access API, Chromium page contexts only, handle in IndexedDB `boersenampel-sync`), `lib/sync-flush.js` (`flushOutboxWith(adapter, storage, producer)` shared by worker and popup). Loaded via `importScripts` (Chrome), `background.scripts` (Firefox) and popup.html; `sync-folder.js` only in popup.html.
- **Storage:** `settings.sync {enabled, adapter:'webdav'|'folder', url, user, password, producerId (UUID, created on first save), label}`, `syncOutbox` (events not yet written, cap `SYNC_OUTBOX_MAX` 2000 → loss sets `needsSnapshot`), `syncDays {day → own events}` (last 7 days — a day file is ALWAYS rewritten whole, WebDAV has no append), `syncMeta {seq, lastFlushAt, lastError(At), lastSnapshotAt, lastSnapshotVersion, needsSnapshot, needsPageFlush, formatWritten}`. Ampel Yahoo symbols live under `quoteSymbols['ampel:'+id]` (`via:'name-search'`, never anchored → `symbol.verified:false` in the export), resolved by `resolveAmpelSymbolsSlowly()` — max 3 name searches per poll.
- **Flow (background.js, "Event-Log-Sync" section):** `ingestSnapshot` → `syncOnAmpelDelta(delta)` (only `!isFirstEver`) and `afterSuccessfulAmpelPoll()` (snapshot rule `maybeEmitSnapshot`: on enable, version change, `needsSnapshot`, else max 1×/24 h; then `flushOutbox`; then slow symbol resolution) — both fire-and-forget, never awaited in the poll path. `doPollCircle` → `syncOnCircleDelta(fresh, modules, oldModules)`. `emitEvents(build)` serializes all outbox writes through `enqueueSync` (seq assignment is a read-modify-write) and writes outbox+meta in ONE `storage.local.set`. `flushOutbox()` has the usual in-flight guard; for adapter `folder` it only sets `syncMeta.needsPageFlush` — popup.js (`pageFlushIfNeeded`, on open, on `storage.onChanged` of `syncMeta`/`syncOutbox`, after Save/Sync-now) performs the write in the page context and reports `syncFlushed`. `syncActive()` gates everything: enabled + producerId + no `DEBUG_SIMULATE`; snapshots additionally require `meta.lastPollOk` (privacy rule), Circle data only with `circleMeta.lastPollOk`.
- **Messages:** `setSync {patch}` (validates URL, creates producerId, on enable → immediate snapshot), `syncTest`, `syncNow` (forced snapshot + flush), `getSyncStatus`, `syncFlushed`, `syncSnapshotJson` ("Snapshot kopieren", works without the switch but only logged in). `publicSync()` masks the password.
- **Permissions:** `optional_host_permissions: ["https://*/*","http://127.0.0.1/*","http://localhost/*"]` in both manifests; the popup requests exactly `origin + '/*'` inside the Save/Test click handler (user gesture). The app shim has no `permissions` API → skipped.

- **HIDDEN since v0.8.3 (user decision 31.08.2026):** the sync feature must not be visible or mentioned to users in this version — `#syncBlock` carries `hidden` in popup.html (code, storage, messages and the flush logic are untouched and still run if `settings.sync.enabled` was set), the user-facing sections were removed from README.md and ANLEITUNG.md, and the 0.7.0 / App 0.7.3 changelog entries were neutralised.
